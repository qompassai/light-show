# Aseprite source pipeline

This folder holds Aseprite-ready copies of Light Show's shipped pixel art,
plus a headless import script, so the art can be opened, animated
further, and re-exported without hand-slicing PNGs again.

## Layout

- `seraphine_sheet.png`, `ondine_sheet.png`, `linka_sheet.png`,
  `lattice_sheet.png` — the four companion sprite sheets, 256×384px
  (4 columns × 6 rows @ 64×64/frame). Row order is fixed by
  `game/src/waifu/sprite.rs`'s `Mood` enum and documented in
  `docs/ART_STYLE.md`: **Idle, Blush, Wink, Pout, Celebrate, Alarmed**.
  Source of truth for regenerating these from scratch is
  `tools/gen_companion_art.py`.
- `component_icons/*.png` — the nine OSP component icons (single frame
  each, 64×64, transparent background), generated by
  `tools/gen_placeholder_art.py`. No rows/tags to slice — open these
  directly in Aseprite rather than through `import_sheet.lua`.
- `import_sheet.lua` — headless Aseprite script that slices a companion
  sheet back into a real multi-frame `.aseprite` document with one
  named tag per mood row.

## Turning a sheet into an editable `.aseprite` document

Requires a real Aseprite install (this repo's sandbox tooling can
generate/verify the PNGs but has no Aseprite binary itself, so this
command has been reviewed but not run here):

```sh
aseprite -b --script art/aseprite/import_sheet.lua -- \
  art/aseprite/seraphine_sheet.png 64 64 \
  Idle Blush Wink Pout Celebrate Alarmed
```

Repeat for `ondine_sheet.png`, `linka_sheet.png`, and `lattice_sheet.png`
with the same 6 tag names (the row order is identical across all four
companions by design — see `docs/ART_STYLE.md`). This writes
`<name>_sheet.aseprite` next to each source PNG, with each frame's
duration set to 180ms to match the in-game animation rate
(`Timer::from_seconds(0.18, TimerMode::Repeating)` in
`game/src/waifu/mod.rs`).

## Editing and shipping changes back

Once you have a `.aseprite` document, the
[Diver Neovim Aseprite actions](https://github.com/qompassai/Diver/blob/main/lua/utils/games/aseprite/actions.lua)
(`<leader>` menu → "Select Aseprite action" → **Export sprite sheet +
JSON**, or **Export tileset (choose sheet type)** for packed/rows/columns
layouts) re-export a flattened PNG + JSON atlas from inside Neovim via
`aseprite -b <sprite> --sheet out.png --data out.json --format
json-array` — no need to touch the Aseprite GUI's own export dialog.

After re-exporting, copy the refreshed PNG over the matching file under
`game/assets/sprites/<companion>/<companion>_sheet.png` (or
`game/assets/sprites/components/<name>.png`) and re-run
`cargo test --workspace` — `game/src/waifu/mod.rs`'s
`mood_sheet_rows_are_unique_and_within_bounds` and `game/src/board.rs`'s
`every_component_icon_path_actually_exists_under_game_assets` fail
loudly if a mood-row mapping or icon file goes missing/out of range,
instead of silently shipping a broken sheet. Frame pixel dimensions
themselves aren't asserted by an automated test today — visually check
a re-exported sheet against the 256×384/64×64 contract before shipping
it (see `docs/ART_STYLE.md`).

## Palette

Sync the game's palette into Aseprite's color bar so new frames stay
on-model — see `docs/ART_STYLE.md` for the full hex list. Export a
`.gpl` palette from any of the source sheets (Aseprite action **Export
palette (.gpl)**) and sync it via **Sync palette into Aseprite user
config**, which copies it to Aseprite's own palette directory
(`~/.config/aseprite/palettes` on Linux).
